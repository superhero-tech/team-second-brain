# Query shared knowledge

- Use the current team clone or select the team from the private brain's `8-System/team-context.md`. Verify repository identity and revision using [Git reads](../../../docs/git-read.md). For `cached`, report the SHA and freshness limitation; for `unavailable`, say shared knowledge could not be checked.
- Read the context map, relevant index and needed pages from one SHA. Follow decisions to their evidence. Read a `superseded` page with its successor; identify `needs_review` pages as awaiting verification.
- Answer with sources and the SHA. Distinguish observations, hypotheses, gaps, private proposals and open PRs from accepted team knowledge. For conflicting team pages, show both sources, identify the authoritative source if known and name the owner who must resolve the conflict. Do not save an answer as new knowledge unless asked to update it.
