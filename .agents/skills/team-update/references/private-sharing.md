# Sharing private material

- Make the contribution understandable without access to private files. For restricted originals, use a shareable extract or attributed account and state the limits.
- A request to save an identified plan, note or result in the team repository authorizes publishing that material in a Draft PR, including necessary formatting, sources and index links. A private source alone is not a reason to ask again. A chat reference authorizes the requested result, not the entire conversation or other private files.
- Ask for approval of the exact proposed disclosure only when the requested material is ambiguous, includes private-only content, needs additional private material, or the user requested a preview first. Honor an approved `team-share` preview; do not ask twice. A Draft PR is visible to the target repository audience.
- Before pushing, inspect the full outgoing scope: files, attachments, commit messages, PR description and links. Exclude private-only content and local paths or chat links that the team cannot access; use a shareable source account instead.
- Use a team branch based on accepted knowledge. Inspect all outgoing commits, including content removed before the final diff. Only the approved shared material and its shareable evidence may leave the private environment.
