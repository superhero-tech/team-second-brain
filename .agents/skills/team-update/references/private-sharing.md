# Sharing private material

- Make the contribution understandable without access to private files. For restricted originals, use a shareable extract or attributed account and state the limits.
- Before any publication, show the exact scope: diff, files, attachments, commit messages, PR description and links. Obtain approval unless that exact scope was already approved in the current conversation. Show changed disclosure scope for approval again. A Draft PR publishes to the target repository.
- Use a team branch based on accepted knowledge. Inspect all outgoing commits, including content removed before the final diff. Only the approved shared material and its shareable evidence may leave the private environment.
