# Knowledge maintenance

| Trigger | Action |
| --- | --- |
| Before work | Read relevant decisions, evidence and gaps. |
| Research, an experiment or a decision changes knowledge | Update affected pages through a PR. |
| Someone finds an error | Propose a correction or an Issue with evidence and an owner question. |
| Weekly, as a starting cadence | The steward reviews Issues and PRs and selects the most useful repairs. |
| Project closure | Write a summary and update reusable knowledge pages. |
| Team changes | Transfer ownership and pending reviews. |

Use [team-garden](../.agents/skills/team-garden/SKILL.md) to report problems and proposed actions. GitHub Issues hold the maintenance queue. Resolve factual conflicts with the responsible people before repairing pages; link the fix PR to the Issue.

Keep superseded pages with a link to their successor. Change `reviewed_at` only after actual content review. The cadence is a starting point, not a claim that a weekly review occurred.
